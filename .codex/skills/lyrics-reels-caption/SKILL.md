# Lyrics Reels Caption

Kotonoha 인스타그램 노래 소개 릴스의 설명란(캡션)을 만드는 워크플로. 결과물은 붙여넣기만 하면 되는 완성 텍스트이며, 마지막에 클립보드에 복사한다.

## 입력

사용자에게서 받을 것. 없으면 기본값으로 진행하고 마지막에 알린다.

- 곡명, 아티스트 (필수)
- 릴스에 쓴 가사 구간 (있으면 그 줄을 우선 인용)
- 개인 감상 한 줄 (없으면 "개인적으로는 …" 문단을 무난한 해석으로 채우고, 사용자 본인 의견으로 바꿔 달라고 알림)

## 워크플로

1. **조사 (WebSearch / WebFetch)** — 아래 항목을 각각 출처와 함께 확보한다.
   - 기록·성과: 차트 순위, 조회수, 수상, 밀리언 등 숫자로 말할 수 있는 것
   - 제작 배경: 타이업(드라마/애니/게임), 가제, 아티스트 본인 발언(인터뷰 인용)
   - 사운드·보컬 특징, 곡의 인상
   - 검색은 일본어로 (`歌詞 意味 考察`, `記録 再生回数 Billboard Japan 年間`).
   - **가사는 웹에서 찾지 않는다.** 아래 2단계에서 dev DB를 쓴다.
2. **가사 조회 (dev DB)** — `scripts/lyrics.sh` 로 k3s `main` 네임스페이스의 MySQL에서 가져온다. 이것이 가사 원문의 유일한 출처다.
   ```bash
   S=.codex/skills/lyrics-reels-caption/scripts
   bash $S/lyrics.sh Lemon                  # 곡 검색 → id 확인 (title/artist LIKE)
   bash $S/lyrics.sh --id 63                # 가사 전체 (index, text)
   bash $S/lyrics.sh --id 63 --tokens       # 줄마다 앱 분석 토큰: 표층(읽기)←기본형 뜻
   ```
   - 곡이 없거나 `lyric_rows` 가 0이면 멈추고 사용자에게 알린다 (앱에서 곡을 먼저 추가해야 함). 웹 가사로 대체하지 않는다.
   - 같은 song_id 에 lyrics 행이 여러 개면 가장 최근 행(MAX(id))을 쓴다. 스크립트가 이미 그렇게 동작한다.
   - 다른 네임스페이스는 `NAMESPACE=reels-factory bash $S/lyrics.sh ...`.
3. **가사 줄 선정** — 4~5줄. 기준: 곡의 핵심 정서를 담고, 초중급 학습자가 건질 어휘·문법이 1~2개씩 있는 줄. 제목 단어는 첫 항목으로 따로 설명한다. 인용은 DB `text` 를 글자 그대로 쓴다 (띄어쓰기·표기 포함).
4. **어휘·문법 정리** — `--tokens` 출력의 읽기·뜻을 기준으로 줄마다 `・단어(읽기) 뜻` 1~3개, 문법 1개 안팎. 읽기는 토큰의 가타카나를 히라가나로 바꿔 적는다. 축약형(〜てる, 〜じゃない, 〜なきゃ) 은 원형을 함께 적는다. **JLPT 급수는 쓰지 않는다** (공식 목록이 없어 출처마다 달라 뺐다).
5. **작성** — `references/format.md` 의 골격과 `references/examples.md` 의 톤을 따른다.
6. **사실 검수** — 게시 전 사용자에게 아래 3층으로 나눠 보고한다 (사용자가 "전부 팩트야?" 라고 묻기 전에 먼저).
   - 출처로 확인한 것
   - dev DB 에서 확인한 것 (가사 원문, 어휘 읽기·뜻)
   - 기억에 의존해 미확인인 것 (앨범, 문법 설명 등)
   - 해석·의견인 것 → 본문에서 반드시 "~라는 해석이 있어요" / "개인적으로는" 으로 표시되어 있는지 확인
   - 해설 기사 필자의 해석을 아티스트 본인의 의도처럼 쓰지 않는다. 본인 발언은 "본인은 … 라고 표현했습니다" 처럼 인용 주체를 명시한다.
7. **글자수 확인** — 최종안을 scratchpad 파일에 저장하고 `scripts/check_caption.sh` 로 검사한다. 통과 못 하면 줄여서 다시 검사한다.
   ```bash
   bash .codex/skills/lyrics-reels-caption/scripts/check_caption.sh "$SCRATCHPAD/caption.txt"
   ```
   - 인스타그램 제한: 본문 **2,200자**(코드 포인트, 해시태그 포함), 해시태그 **30개**. 스크립트는 2,000자 초과 시 WARN, 2,200자·30개 초과 시 FAIL.
   - 길이를 줄일 때 순서: 가사 줄 5→4개 → 줄당 어휘 항목 축소 → 소개 2·3문단 압축. 곡 정보·CTA·해시태그는 유지.
   - 릴스는 설명란 첫 **약 55자**, 피드는 약 125자만 보이고 "더 보기"로 접힌다. 파일은 첫 줄이 곧 제목(`{아티스트}「{곡명}」 가사로 배우는 일본어`)이 되도록 앞에 빈 줄을 두지 않는다. 스크립트가 미리보기 구간을 출력하니 확인한다.
8. **클립보드 복사** — 검사를 통과한 파일을 `scripts/clipboard.sh` 로 복사한다. 리포트/출처/설명은 복사에 포함하지 않는다. 캡션 본문만.
   ```bash
   bash .codex/skills/lyrics-reels-caption/scripts/clipboard.sh < "$SCRATCHPAD/caption.txt"
   ```
9. **보고** — 캡션 전문, 사실 검수 3층, 참고 출처 링크, 글자수 검사 결과(N/2,200), 복사 완료 여부를 순서대로 알린다.

## 톤 규칙

- 해요체와 합니다체 혼용. 문단 끝은 "~입니다 / ~했어요 / ~있어요" 로 맺는다.
- **"~다고." 처럼 인용을 서술어 없이 끊는 문장 금지.** ("다시 썼다고." ✗ → "다시 썼어요." ✓)
- 너무 건조하면 안 된다. 곡을 좋아하는 사람이 소개하는 온도. 마지막 문단에 "직접 해석해 보는 재미가 있어요" 류의 권유 한 문장을 둔다.
- 영어 직역 신조어·전문 용어 금지. 평이한 한국어.
- 숫자·기록은 출처 확인된 것만. 못 확인했으면 빼거나 사용자에게 알린다.
- JLPT 급수와 면책 문구는 넣지 않는다.

## dev DB

- 접속: `kubectl -n main exec -i mysql-0 -- mysql ...`. 자격 증명은 파드 env(`MYSQL_USER`/`MYSQL_PASSWORD`/`MYSQL_DATABASE`)에서 읽으므로 로컬에 비밀값이 필요 없다. 반드시 `--default-character-set=utf8mb4` (없으면 일본어가 `????` 로 나온다).
- 스키마: `songs(id, title, artist)` ← `lyrics(song_id, raw_content JSON, analyzed_content JSON)`. `raw_content` 는 `[{index, text, startTimeMs}]`, `analyzed_content` 는 `[{index, tokens:[{surface, reading, baseForm, koreanText, ...}]}]`.
- 셸에서 `$[*]` 같은 JSON 경로가 변수 확장되지 않도록 SQL 은 quoted heredoc 으로 stdin 에 넘긴다 (`-e "..."` 안에 `$` 를 쓰면 깨진다).

## 클립보드

`scripts/clipboard.sh` 는 stdin 을 받아 `wl-copy` → `xclip` → `xsel` → `pbcopy` 순으로 사용 가능한 도구에 복사한다. 이 머신은 Wayland (`wl-copy`). 도구가 없으면 종료 코드 1 과 함께 안내 메시지를 내므로, 그때는 캡션을 터미널에 그대로 출력하고 복사 실패를 알린다.
