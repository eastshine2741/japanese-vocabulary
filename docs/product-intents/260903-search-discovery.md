# Product Intent: Search Discovery

## 사용자 목표

- 사용자는 직접 검색해 원하는 일본 노래를 찾을 수 있다.
- 사용자는 추천곡과 최근 찾아본 곡에서 새 학습 후보를 발견할 수 있다.
- 사용자는 관심 있는 곡을 선택해 `SongDetailScreen`으로 진입할 수 있다.

## 현재 문제

- 현재 검색탭은 최근 검색 기록 중심이라 새 곡을 발견할 단서가 부족하다.
- 사용자는 검색어를 이미 알고 있을 때만 곡 탐색을 시작하기 쉽다.
- 추천곡과 최근 찾아본 곡의 역할이 분산되어 다음 학습 후보를 고르기 어렵다.

## 성공 기준

- 사용자는 검색어 없이도 탐색할 곡 후보를 볼 수 있다.
- 사용자는 검색, 추천곡, 최근 찾아본 곡 중 하나에서 곡을 선택할 수 있다.
- 사용자가 곡을 선택하면 해당 곡의 `SongDetailScreen`으로 이동한다.
- 검색탭은 새 학습 재료를 찾는 화면으로 인식된다.

## Scope

- 검색탭의 제품 역할 재정의
- 직접 검색 진입점
- 추천곡 진입점
- 최근 찾아본 곡 진입점
- 곡 선택 후 `SongDetailScreen` 이동
- 검색 결과, 추천곡, 최근 찾아본 곡의 상태 처리

## Non-goal

- `SongDetailScreen`의 학습 시작 UX 구현
- 홈탭 카드 스택 구현
- `StudySessionScreen` 구현
- 프로필탭 또는 학습 통계 화면 구현
- 추천곡 선정·정렬 알고리즘 변경
- 최근 찾아본 곡 저장 정책 변경
- 검색 API 변경
- 음악 재생 중심 탐색 기능
- SNS식 피드, 좋아요, 팔로우, 댓글, 공유 기능

## 주요 플로우

1. 사용자가 검색탭에 진입한다.
2. 시스템은 검색 진입점과 탐색 가능한 곡 후보를 보여준다.
3. 사용자는 직접 검색하거나 추천곡, 최근 찾아본 곡 중 하나를 확인한다.
4. 사용자가 관심 있는 곡을 선택한다.
5. 시스템은 선택한 곡의 `SongDetailScreen`으로 이동시킨다.
6. 결과적으로 사용자는 곡 탐색에서 곡 기반 학습 판단으로 이어진다.

## 사이드케이스 플로우

### 검색어가 없는 경우

1. 사용자가 검색어 없이 검색탭에 진입한다.
2. 시스템은 추천곡과 최근 찾아본 곡을 보여준다.
3. 결과적으로 사용자는 검색어를 입력하지 않아도 곡 탐색을 시작할 수 있다.

### 검색 결과가 없는 경우

1. 사용자가 검색어를 입력한다.
2. 시스템은 검색 결과가 없음을 알려준다.
3. 결과적으로 사용자는 다른 검색어로 다시 탐색할 수 있다.

### 최근 찾아본 곡이 없는 경우

1. 사용자가 최근 찾아본 곡이 없는 상태로 검색탭에 진입한다.
2. 시스템은 최근 찾아본 곡 영역을 비워 두지 않고 다른 탐색 후보를 유지한다.
3. 결과적으로 사용자는 추천곡 또는 직접 검색으로 탐색을 계속할 수 있다.

### 추천곡을 불러오지 못한 경우

1. 사용자가 검색탭에 진입한다.
2. 시스템은 추천곡 없이 검색과 최근 찾아본 곡을 유지한다.
3. 결과적으로 사용자는 추천곡 장애와 무관하게 곡을 탐색할 수 있다.

### 곡 상세 진입 실패

1. 사용자가 곡을 선택한다.
2. 시스템은 `SongDetailScreen`의 기존 오류 처리를 따른다.
3. 결과적으로 검색탭은 별도의 상세 오류 정책을 갖지 않는다.
