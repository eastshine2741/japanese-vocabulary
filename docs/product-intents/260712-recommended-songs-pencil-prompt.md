# Pencil Desktop Agent Prompt: 추천곡 섹션

아래 프롬프트 전체를 Pencil Desktop App의 에이전트에게 입력한다.

---

현재 저장소의 React Native 앱 홈 화면에 들어갈 **추천곡 섹션을 Pencil에서 디자인해줘.** 코드 구현은 하지 말고 `.pen` 디자인만 편집해.

## 작업 파일과 안전 규칙

1. 작업 전에 반드시 `open_document`로 현재 워크트리의 아래 파일을 직접 열어:
   - `/home/eastshine/IdeaProjects/japanese-vocabulary-feature-recommended-songs/app-rn/japanese-vocabulary.pen`
2. `get_editor_state`가 다른 경로를 가리키고 있으면 그 문서를 편집하지 마.
3. 기존 `R1. 홈 탭 (Home)` 프레임과 그 안의 컴포넌트·변수·타이포그래피를 먼저 살펴봐.
4. 원본 프레임을 덮어쓰지 말고 복제본에서 작업해. 완성 프레임 이름은 다음과 같이 지정해:
   - `R1 Recommended. 홈 탭 (Home)`
   - `R1 Recommended Loading. 홈 탭 (Home)`
5. Spotlight, 학습 통계, 단어 복습, 최근 찾아본 노래, 앱 바, 탭 바의 기존 디자인은 변경하지 마. 추천곡 삽입에 필요한 세로 위치와 프레임 높이만 조정해.
6. 디자인을 마친 뒤 두 프레임을 나란히 배치하고, 사용자가 Pencil Desktop에서 `Ctrl+S`로 저장해야 한다고 알려줘.

## 제품 맥락

Kotonoha는 일본 노래의 가사를 보며 단어를 학습하는 앱이야. 추천곡 섹션의 한 가지 역할은 사용자가 홈에서 흥미로운 일본 노래를 발견하고 `SongDetailScreen`으로 들어가게 하는 것이야.

- 신규 사용자에게도 과거 활동 없이 콘텐츠를 제공한다.
- 추천곡이 있으면 신규·기존 사용자 모두에게 표시한다.
- 홈의 `단어 복습` 섹션 바로 아래, `최근 찾아본 노래` 섹션보다 위에 배치한다.
- 최대 10곡을 가로로 탐색하지만 모든 곡은 동등한 위계를 가진다.
- 추천곡은 운영자가 고른 주간 셀렉션이지만 순위 차트가 아니다.

## 확정된 UI 구조

섹션 문구는 정확히 다음을 사용해:

- 제목: `이번 주 추천곡`
- 보조 문구: `요즘 많이 듣는 일본 노래`

추천곡은 **대형 앨범 슬리브 캐러셀**로 디자인해:

- 모든 곡 카드는 같은 크기와 같은 시각 스타일을 사용한다.
- 카드 너비는 화면 너비의 약 65~70%를 기준으로 하되 기존 홈 여백과 조화롭게 보정한다.
- 정사각형 앨범 커버를 카드의 시각적 중심으로 크게 보여준다.
- 곡 제목과 아티스트는 커버 아래에 배치한다. 앨범아트 위에 텍스트를 겹치지 않는다.
- 두 곡 이상일 때 다음 카드의 일부가 오른쪽에 보여야 한다. 이것이 가로 스크롤의 주된 힌트다.
- 캐러셀은 카드 단위로 스냅되는 구조가 시각적으로 이해되어야 한다.
- `최근 찾아본 노래`의 작은 앨범 카드보다 확실히 크고 여유로운 밀도를 사용한다.
- 카드 전체가 탭 영역임을 자연스럽게 느낄 수 있어야 한다.

## 시각 방향

이번 디자인의 유일한 강한 시각적 강조는 **앨범 커버의 크기와 존재감**이야.

- 현재 Pencil 문서의 색상 변수, 폰트, 모서리 체계, 화면 여백을 우선 사용해.
- 큰 커버, 정교한 간격, 절제된 테두리 또는 그림자 중 필요한 최소 요소만 사용해.
- 추천곡 섹션은 최근 곡보다 눈에 띄어야 하지만 Spotlight와 경쟁하는 두 번째 hero처럼 보이면 안 돼.
- 여러 장식 효과를 겹치지 마. 커버가 충분히 강하면 별도 배경 그래픽이나 배지는 제거해.
- 실제 콘텐츠로 검토할 수 있도록 일본어 곡 제목과 아티스트가 서로 다른 샘플 카드 3개 이상을 사용해. 모든 카드의 중요도는 같아야 해.
- 긴 곡 제목과 긴 아티스트명이 각각 한 줄에서 말줄임되는 상황도 한 카드에 보여줘.

## 금지 사항

다음 요소는 사용하지 마:

- 순위 숫자, 순번, `TOP 10` 표현
- 첫 곡만 크게 만드는 featured 카드
- 페이지 인디케이터 dot
- 오비 스트립
- `NEW`, `HOT`, 장르 등의 배지
- 앨범 커버 위 텍스트 오버레이
- 곡별 소개 문구 또는 별도 CTA 버튼
- 추천곡 전체보기 링크나 화면
- 새로운 폰트 또는 홈 전체 색상 팔레트 변경
- 기존 Spotlight 디자인 변경

## 정상 상태 프레임

`R1 Recommended. 홈 탭 (Home)`에는 다음을 보여줘:

1. 기존 홈 전체 맥락
2. 단어 복습 바로 아래의 추천곡 제목과 보조 문구
3. 동일 크기의 추천곡 카드 최소 3개
4. 첫 카드 전체와 다음 카드 일부가 보이는 초기 스크롤 위치
5. 추천곡 다음에 이어지는 기존 `최근 찾아본 노래` 섹션

화면 프레임 높이는 추천곡과 최근 곡의 상대적 위치가 검토 가능하도록 충분히 늘려도 돼. 모바일 화면 폭은 기존 R1 프레임을 유지해.

## 로딩 상태 프레임

`R1 Recommended Loading. 홈 탭 (Home)`은 정상 상태 프레임을 복제해 만들고 추천곡 영역만 로딩 상태로 바꿔:

- 제목과 보조 문구는 그대로 표시한다.
- 실제 카드와 같은 크기·간격의 스켈레톤을 표시한다.
- 스켈레톤도 다음 카드 일부가 보이는 캐러셀 구조를 유지한다.
- shimmer의 한 순간을 정적인 Pencil 시안으로 표현하려고 과도한 그라디언트를 사용하지 마.
- 다른 홈 섹션은 정상 상태 프레임과 같아야 한다.

빈 결과와 최초 조회 실패 때는 추천곡 섹션 전체가 숨겨지므로 별도 empty/error 프레임은 만들지 않아도 돼.

## 완료 전 자체 검토

완료 전에 다음을 직접 확인하고 어긋나면 수정해:

- 추천곡이 단어 복습 아래, 최근 찾아본 노래 위에 있는가?
- 추천곡 카드 사이에 순위나 크기 위계가 없는가?
- 앨범 커버가 최근 곡 카드보다 확실히 크고 눈길을 끄는가?
- 다음 카드 일부가 보여 별도 dot 없이도 가로 스크롤을 이해할 수 있는가?
- Spotlight보다 더 강한 hero로 보이지 않는가?
- 제목과 아티스트가 앨범아트를 가리지 않는가?
- 금지 요소가 하나도 들어가지 않았는가?
- 정상 상태와 로딩 상태 외의 기존 홈 디자인이 동일하게 보존됐는가?

마지막 응답에는 디자인한 프레임 이름, 선택한 정확한 카드 너비·간격, 기존 디자인 시스템에서 재사용한 토큰, 자체 검토 결과를 간단히 정리해줘.
