# 보상 카드 (곡 카드 · 아티스트 카드)

Pen `app-rn/japanese-vocabulary.pen` 의 `P3a. Profile — 카드 탭` / `P3b. Profile — 학습 탭`,
`component/songCard` · `component/artistCard`, `spec/songCard states` 가 원본이다.
앱은 서버 카드(`GET /api/reward-cards`)를 그린다. 개발 빌드에선 화면 왼쪽 위 `카드: 서버|더미` 칩으로 더미 데이터
(`app-rn/src/components/rewardCards/dummyRewardCards.ts`, 모든 등급 견본)로 바꿔 볼 수 있다. 더미를 보는 동안엔 서버 연출을 띄우지 않는다(서버에 남아 나중에 뜬다).

## 곡 카드 — 등급마다 새로 발급하고, 순번도 등급마다 센다

한 장을 강화하지 않고 조건을 채울 때마다 그 등급 카드를 새로 준다. 받은 카드는 모두 남아(한 곡에 최대 5장) 등급은 바뀌지 않는다.
순번("N번째 획득")을 곡·등급마다 따로 세서, 같은 곡을 공부하는 유저끼리 다음 등급을 누가 먼저 받는지가 순번으로 남는다 — 그 순서 경쟁으로 다음 단계를 공부하게 한다.
한 번의 rating 으로 여러 단계가 함께 끝나면 낮은 등급부터 카드가 차례로 나온다.

| 등급 | 조건 | 카드 |
|---|---|---|
| 기본 | 곡 단어를 하나라도 공부 (첫 rating) | 무광 종이 `◇◇◇` |
| BRONZE | 후렴 정복 단계 단어를 전부 공부 (남음 0) | 동 테 · 동박 제목 `◆◇◇` |
| SILVER | 따라 부르기 단계 단어를 전부 공부 | 은 테 · 은박 제목·세로 가사 `◆◆◇` |
| GOLD | 완곡 단계 단어를 전부 공부 | 금 테 · 금박 제목·세로 가사 · 아트 홀로·글리터 `◆◆◆` |
| MASTER | 곡 단어의 **90%** 가 장기기억 (`stability >= 14`) | 마스터 카드 (렌티큘러 인쇄 앞면) |

- 등급과 이름은 아티스트 카드(종이 → 동 → 은 → 금)와 같다. 마스터는 아티스트의 PLATINUM·DIAMOND 와 섞이지 않게 MASTER 로 따로 둔다.
  두 사다리는 이어지지 않는다 — 아티스트 등급은 마스터 곡 수로만 정해진다.
- 등급 차이는 테에 힘을 주지 않고 박이 차지하는 자리(제목 → 세로 가사 → 아트 전체)로 낸다. 뒷면에는 테가 없어서,
  뒷면 몸체를 앞면 테와 같은 등급 색으로 칠해 앞뒤를 잇는다 (마스터 뒷면은 곡 색 몸체).

마스터 카드의 렌티큘러 앞면은 그림 두 장(앞면 ↔ 장면 B)뿐이라 단계마다 줄 수 없다. 레벨마다 주면 레벨이 오르는 순간
범위가 넓어져 마스터가 꺼지고, 한 번 준 마스터를 유지하면 다음 단계를 공부할 이유가 사라진다.
그래서 완곡 다음의 마지막 보상 하나로 둔다. 어느 시점이든 다음 목표는 하나다.

마스터를 '전부'가 아니라 90% 로 두는 건, 정직하게 공부해도 due 마다 약 10% 는 잊혀 stability 가 떨어지기 때문이다.
'전부'는 곡 단어가 많을수록 모두 동시에 넘는 날이 드물어져 반년 넘게 걸리고 곡마다 들쭉날쭉하다. prod 곡 단어 수
(중앙값 78, p10~p90 48~124)로 시뮬레이션하면 90% 는 곡 길이와 상관없이 약 6주다.

## 낡음 — 복습할 때가 된 단어 비율로 잰다

```
due = 지금 복습할 차례인 단어 수 / 카드를 받은 뒤 리뷰한 tier 단어 수   // 잴 단어가 없으면 0
age = clamp((due − 0.2) / 0.8, 0, 1)
```

- 첫날만 하고 떠날 유저를 다음 날 다시 부르려고 R 대신 due 를 쓴다. FSRS R 은 하루 단위로 끊어 계산해서 마지막 리뷰 뒤 24시간 안엔
  늘 100% 라 다음 날 카드가 낡지 않는다. 반면 prod 에서 첫날만 공부한 유저 단어의 71% 는 다음 날 이미 due 다('쉬움' 26% 만 졸업하고,
  나머지는 몇 분 뒤 학습 단계 복습을 남긴 채 앱을 닫는다). 스케줄은 건드리지 않는다 — 쉽다고 매긴 단어는 쉬운 대로 둔다.
- '쉬움' 단어도 간격이 지나면 due 가 돼서, 오래 떠날수록 비율이 계속 오른다.
- 등급과 상관없이 곡의 tier 단어 전부로 잰다. 단어 기억은 곡마다가 아니라 하나라서, 받기 전 리뷰까지 세면 다른 곡에서 공부하고
  밀린 단어 때문에 받자마자 낡은 카드가 나온다. 그래서 받은 뒤 리뷰한 단어만 센다.
- due 는 지금 시각 기준이라, 받은 뒤 같은 세션에서 매긴 단어의 학습 단계가 몇 분 뒤 돌아오면 그날 바로 낡아 보일 수 있다.
- 구간: 새것 < 20% · 빛바램 < 50% · 낡음 < 90% · 너덜너덜. 코팅 `(1 − age)^1.6` 이 포일·반사광·금속 테 명암을 함께 줄여, 끝엔 무광 종이만 남는다.
- 레벨·마스터는 저장하는 이벤트, 낡음은 조회 때 계산한다.
- 손상은 age 가 오를수록 차례로 붙는다: 빛바램·잔흠집(기울이면 빛을 받음) → 모서리가 하얗게 닳고 얼룩·가로 접힘
  → 모서리 접힘·세로 접힘·코팅이 벗겨져 판지가 드러남 → 찢어져 누런 테이프로 붙인 자국. 카드 id 시드라 늘 같은 자리다
  (`wearGeometry.ts`, 질감은 `app-rn/assets/cards/`).

## 곡 카드 가사 — 주인이 고른다

- 앞면 세로쓰기와 뒷면(후리가나·번역)에 싣는 가사는 주인이 곡 전체에서 1~2줄 고른다. 공부한 단계로 제한하지 않는다.
- 뒷면 단어 5개는 그 고른 줄에 나오는 단어에서 중요한 순으로 뽑는다. 줄을 바꾸면 단어도 바뀌고, 줄에 단어가 적으면 5개보다 적게 싣는다.
- 카드를 처음 얻는 순간 전체 화면 획득 연출(`RewardCardReveal` 화면)이 뜨고, 거기서 `가사 고르기` 로 바로 고르거나
  `이대로 받기` 로 기본 줄을 그대로 받는다. 연속 학습 축하처럼 조건이 채워지면 스스로 뜨며(`rewardCardStore.reveal` →
  `RewardCardRevealHost` 가 화면을 연다), 축하 화면이 떠 있으면 그게 닫힌 뒤에 뜬다. 오버레이가 아니라 스택 화면인 건 아래 화면이
  매 프레임 다시 합성되어 카드 효과가 끊기기 때문이다.
- 획득 화면 첫 단계엔 칩·곡명·아티스트명을 두지 않는다(카드에 이미 있다). 대신 카드 위에 '곡 카드를 얻었어요' 한 줄,
  아래에 이 카드가 무엇인지 두 줄과 승급 계단(기본·BRONZE·SILVER·GOLD·MASTER, 각 조건 = 단계 이름)을 두고 지금 자리를 짚는다.
  따로 튜토리얼 없이 처음 받는 순간에 규칙을 알게 하려는 것이다. 아티스트 카드는 같은 자리에 등급 계단(기본~DIAMOND, 마스터 곡 수)을 둔다.
- 낡음은 첫 곡 카드를 받을 때 서명 뒤 화면 하나(`CardWearIntro`)로 한 번만 설명한다. 방금 받은 카드 아래 '복습할 때가 된 단어' 슬라이더
  (0% → 100%, 20% 눈금)가 들어오자마자 저절로 왼쪽에서 오른쪽으로 움직여 카드가 낡아 가는 걸 보여 주고, 끌어서 직접 볼 수도 있다.
  구간 이름은 쓰지 않고 제목 '카드가 낡지 않게 자주 복습해주세요' 아래 '공부한 단어는 며칠 뒤 다시 복습할 때가 와요 / 그런 단어가 쌓일수록 카드가 낡고, 복습하면 다시 새것이 돼요' 두 줄만 적는다. 본 적이 있는지는 아직 메모리에만 있어 앱을 다시 켜면 다시 뜬다.
  곡 카드 상세의 `복습할 때가 된 단어 (i)` 를 누르면 이 화면만 다시 뜬다(본 것으로 치지 않고, 뒤로 가기로 닫힌다).
- 채우기(아래 '카드 전 기록 채우기')로 받은 카드는 획득 화면을 거치지 않는다. 그래서 낡음 설명을 본 적 없는 유저가 발급된 곡 카드 상세에
  들어오면 경로(알림·프로필·곡 상세)와 상관없이, 같은 획득 화면(`RewardCardReveal`, `intro: true`)을 봉투·서명 없이 연다. '그동안 공부한 곡이 카드가 됐어요'와 카드,
  승급 계단(획득 조건 '첫 학습'부터)을 보여 주고 `다음` 으로 `CardWearIntro` 를 거쳐 상세로 돌아온다. 본 것은 낡음 설명과 같은 플래그로 남긴다.
- 나중에도 카드 상세의 편집 버튼(`RewardCardLyricEdit`)에서 언제든 바꾼다. 고르는 대로 미리보기 앞면이 바뀌고, 2줄이 찬 채로
  새 줄을 누르면 먼저 고른 줄이 빠진다.
- 개발 빌드에선 프로필 곡 카드·아티스트 카드를 길게 눌러 획득 화면을 다시 띄운다. 이렇게 띄운 연출의 서명·가사는 서버에 보내지 않는다.

## 곡 카드 서명 — 발급 때 한 번

- 곡 카드 뒷면엔 실물 카드처럼 흰 서명 칸이 있고, 주인이 손으로 그린 서명이 그대로 들어간다.
- 서명은 카드마다 발급 때 한 번만 받고 고칠 수 없다. 획득 화면은 가사를 고르든 그대로 받든 마지막에 서명 단계를 거쳐야 닫히고,
  첫 단계에서 뒤로 가기도 막는다. 도는 동안 보이는 뒷면 서명 칸은 비어 있다.
- 패드와 카드 서명 칸은 같은 3:1 좌표(`SIGNATURE_BOX`)를 써서, 패드에 쓴 그대로 칸에 줄어 들어간다. 긋는 동안 미리보기 카드 칸도 점마다 따라 그린다.
- 서명은 '이 카드는 내 것'이라는 감각을 만드는 의식이다. 서명 단계에선 뒷면 빈 칸을 강조색 점선으로 짚는다(패드는 빈 종이다 —
  ✕·밑줄은 뜻이 전해지지 않아 뺐다). 그리는 대로 뒷면 미리보기 칸에 서명이 들어가고, 확정하면 그 서명된 뒷면 그대로 카드가 앞면으로 돌아선 뒤
  '카드를 획득했어요!'와 '이 곡의 {등급} 카드를 전체 유저 중 N번째로 획득했어요'가 붙는다(발급일은 넣지 않는다). 서명을 확정한 뒤엔 뒤로 갈 수 없다.
- 획득 연출: 큰 봉투가 찢는 띠를 화면 한가운데에 두고 아래 끝은 화면 밖으로 걸친 채 떠오르고 '옆으로 밀어서 뜯기'를 띄운다 — 유저가 윗띠를 밀어 뜯어야(눌러도 뜯긴다) 공개가 시작된다.
  봉투는 카드 색으로 물들고 뒷날개 접힘·절취선이 있다. 카드는 다 뜯기 전엔 그리지 않는다. 손가락이 지나간 자리(x·y)대로 찢기고 찢긴 조각은 손가락 자리를 축으로 들리며, 칸마다 진동, 다 뜯으면 조각이 날아가고 0.3초 숨을 모은다(방이 어두워지고 봉투가 부풀며 찢긴 틈으로 빛이 새고, 진동이 두두두 점점 빠르고 세게). 이어 화면이 한순간 하얗게 날아가며 무거운 두 방. 카드는 1.8초에 걸쳐 봉투에서 화면 가운데로 떠오르며 커지고, 세로축으로 일곱 바퀴(처음 초당 12바퀴) 점점 느려지게 돌아 앞면에서 멈춘다(옆면이 지날 때마다 진동이라 진동도 빠르다가 느려진다, 끝 무렵 조금 세게). 봉투는 아래로 떨어진다. 튕기는 바운스는 쓰지 않는다. 살짝 넘치게 커졌다가 제자리에 박히는 순간 한 번 더 번쩍이고 무거운 두 방+성공 진동·폭죽, 그 뒤에 문구가 올라온다.
  뒷면에도 내용이 있어 엎어 뒀다 뒤집는 공개는 쓰지 않는다(도는 동안엔 뒷면도 비친다). 승급 계단은 지금 자리까지 한 칸씩 차오른다(칸마다 가벼운 진동).
- 최종 지급: 서명된 뒷면을 잠깐 보여 준 뒤 화면이 번쩍이며 무거운 두 방과 함께 앞면으로 한 번 뒤집힌다(여러 바퀴 돌리지 않는다 — 봉투 연출과 겹친다).
  이어 'N번째' 가 0 부터 올라가며 살짝 커지다가(바뀔 때마다 틱) 멈추며 제 크기로 돌아오고 무거운 두 방+성공 진동. 그 뒤 확인 버튼이 눌린다.
- 햅틱(`expo-haptics`, 새 네이티브 빌드 필요): 위 연출, 서명을 확정할 때 가볍게.
- 서명 없이 발급된 카드(더미, 아래 '카드 전 기록 채우기')는 칸에 표시 이름을 대신 찍는다. 나중에 서명하게 하지 않는다 —
  서명은 따낸 순간을 내 카드로 확정하는 동작이라, 이룬 순간 없이 받은 카드에 서명을 요구하면 할 일 목록처럼 귀찮기만 하다.
- 아티스트 카드도 같은 획득 화면(`RewardCardReveal`, `kind: 'artist'`)으로 받는다. 고를 가사가 없어 `서명하기` 하나로 바로 서명 단계에 가고,
  나머지(뒤로 가기 막기·서명 칸 점선·앞면으로 돌아서며 '이 아티스트의 {등급} 카드를 전체 유저 중 N번째로 획득했어요')는 곡 카드와 같다.
- 획득 화면 제목은 기본 카드면 '곡 카드를 얻었어요'·'아티스트 카드를 얻었어요', 그 위 등급이면 '{등급} 카드를 얻었어요'다. 그 위에 큰 축하 한마디를 둔다 — 첫 카드 '축하해요!', 다음 등급 '대단해요!', 마지막 등급 '완벽해요!'. 계단 위 한 줄은
  '단계를 끝낼 때마다 다음 등급 카드를 새로 받아요'(아티스트는 MASTER 곡 카드·등급으로).
  마지막 등급(곡 MASTER·아티스트 DIAMOND)엔 다음 카드가 없어 그 줄을 '이 곡의|이 아티스트의 마지막 등급 카드예요'로 바꾼다.
  아티스트 기본 카드엔 'BRONZE 카드부터 몇 번째 팬인지 번호가 붙어요'를 한 줄 더 둔다 — 기본 카드 앞면엔 팬 번호가 없다.



## 등급 오름 — 새 카드로 받는다

- 다음 등급에 닿으면 이미 가진 카드가 바뀌지 않고 그 등급의 새 카드가 봉투·가사 고르기·서명을 거쳐 나온다(첫 획득과 같은 화면). 마스터·아티스트 등급도 같다.
- 예전엔 한 장을 '눌러서 새기기'로 강화했지만(봉투 없이 박은 자리에서 새 등급이 번짐), 카드가 등급마다 따로가 되면서 걷어냈다. 등급마다 서명을 받아야
  그 순번이 '내가 이 등급에 닿은 순간'으로 남는다.

## 아티스트 카드

'나는 이 아티스트의 팬이다'를 보여 주는 카드다. 곡 카드보다 오래 걸려야 하고, 곡을 더 많이 공부할수록 다음 등급 카드가 나온다.

- 그 아티스트의 첫 곡 카드와 함께 종이 카드로 발급된다. 마스터 곡 수가 다음 구간에 닿을 때마다 그 등급 카드를 새로 발급하고, 순번은 아티스트·등급마다 센다.
- 팬 번호(몇 번째 팬)는 BRONZE 카드의 순번이고, 그 위 등급 카드에도 같은 번호를 싣는다(`fanNo`). 기본 카드는 단어 하나만 담아도 받아
  팬이라 부르기엔 가벼워서 팬 번호가 없다. 등급마다 번호가 새로 매겨지면 같은 팬이 몇 번째인지가 바뀌어 어색하다.
  등급별 순번(`acquiredSeq`)은 획득 화면의 'N번째로 획득했어요'에만 쓴다.
- 기준은 하나, 그 아티스트의 **마스터 곡 카드 수** 다. 이 숫자는 상한 없이 카드에 새겨진다.
- 등급은 숫자가 구간에 닿을 때만 바뀐다. 납찰(納札)처럼 위로 갈수록 구간이 넓어서, 곡이 적은 아티스트도 아래 몇 단계는
  금방 거치고 곡이 많은 아티스트의 팬에게도 위가 남는다. 최고 등급 뒤에도 숫자는 계속 오른다.

| 등급 | 마스터 곡 | 앞면 사진 마감 | 앞면 인증 스티커·빛 | 뒷면 몸체 |
|---|---|---|---|---|
| 종이 | 0 | 무광 인화 (검정이 살짝 뜨고 종이 결) | 붉은 잉크 도장 | 크림 종이 |
| 동 | 1 | 반광 | 동 박 스티커, 빛줄기 + 에칭 | 짙은 초콜릿 + 구리 박 숫자 |
| 은 | 3 | 반광, 대비 조금 더 | 은박 스티커, 빛줄기 + 에칭 | 흑연 + 은박 숫자 |
| 금 | 7 | 유광 (깊은 검정) | 금박 스티커, 글리터 | 검정 + 금박 숫자 |
| 플래티넘 | 15 | 유광 + 더 선명 | 백금 홀로그램 스티커, 글리터 + 은은한 홀로 (무지개 없음) | 밝은 헤어라인 백금 |
| 다이아 | 30 | 유광 + 가장 선명 | 무지개 결정 홀로그램 스티커, 결정면·흰 섬광·무지개 | 투명한 결정면 + 섬광·무지개 |

- 곡 카드(수집 카드)와 달리 회원 카드다. 앞뒷면 모두 테·띠가 없다. 사진 색은 모든 등급이 원본 그대로이고, 등급은 인화 마감
  (`artistPhotoTone.ts`, 대비와 검정이 뜨는 정도만 바꿈. 앱은 Skia ColorMatrix·웹은 CSS 필터)과 그 위의 빛으로만 오른다.
  채도를 깎거나 금속 색을 사진에 덧칠하면 바래거나 누렇게 보여 종이보다 못해진다. 컬러 사진 위 이름에 금속박을 쓰면 색끼리
  부딪혀서 이름은 늘 흰 글씨이고, 박(`FoilText`)은 작은 등급 각인과 뒷면 숫자에만 쓴다. 뒷면은 등급 색으로 만든 몸체이고,
  실제 멤버십 카드처럼 동·은·금은 깊은 색 몸체에 박을 찍는다.
- 앞면 등급은 멤버십 카드 귀퉁이의 정품 인증 홀로그램처럼, 그 등급 색으로 만든 인증 스티커(`CardSeal`)로 보인다. 오른쪽 위에
  두고 `言の葉` 글자를 볼록하게 찍는다. 기울이면 빛 띠가 지나가고 글자 모서리에 빛이 맺힌다. 종이는 붉은 잉크 도장이다.
  IC 칩은 결제 기능이 없어 어색하고, 기념 디스크는 작으면 동전 같고 크게 빼면 사진을 가리고 끝만 비치면 레코드로 안 읽혀 거절했다. 글씨는 왼쪽에 모은다: 위에 몇 번째 팬, 아래에 이름과 그 밑 한 줄(팬이 된 달 · 등급 각인). 빛 효과는 기울일 때만 보이면 썸네일에서 등급이 안 갈려서,
  썸네일은 등급만큼 멈춘 빛(에칭·반짝임 몇 점·홀로·결정면)을 그리고, 상세 화면은 가만히 있어도 빛이 천천히 흔들린다.
- 다이아는 결정면(`FacetLayer`, 기울이면 면이 번갈아 빛남)과 흰 섬광이 바탕이고, 무지개는 그 위에 얹는다. 무지개만 있으면 다이아가 아니라 무지개로 읽힌다.
- 몇 번째 팬·받은 날은 발급 때 고정된다. 지난 등급의 카드는 다음 등급에 닿기 전까지의 마스터 곡만 싣고(그 등급이던 때의 모습),
  가장 높은 등급의 카드만 마스터 곡이 늘 때 숫자가 오른다.
- 낡음은 없다. 마스터는 되돌리지 않는 이벤트이고 등급은 그 수에서 계산한다 (`artistGrade.ts`).
- 앞면은 팬 정보다. 몇 번째 팬(기본 카드는 없음), 팬이 된 달, 아티스트 이름, 등급 이름 각인(종이는 없음)을 왼쪽에 둔다.
  마스터 곡 수는 뒷면에만 있다.
- 뒷면은 마스터 곡 수, 소유자 칸, 최근 마스터한 곡 5개(마스터 순번·제목, 나머지는 '외 N곡')다. 다음 등급까지의 진행은 카드에 넣지 않는다.
  앨범 커버는 곡이 아니라 앨범마다 달라 곡을 가르지 못하므로 제목 옆 작은 곁들임으로만 쓴다.
- 구간 값은 마스터 한 곡에 실제로 걸리는 기간을 보고 다시 맞춘다. 받은 등급 카드는 없애지 않는다.

## 곡 상세·아티스트 상세에서 카드 알리기

카드는 학습의 결과라 학습 데이터보다 앞세우지 않는다.

- 곡 상세 `완곡까지 3단계`: 펼친 단계가 아직 못 받은 카드면 진행 막대와 학습 버튼 사이에 `단계 완료 보상` 줄
  (`BRONZE 카드 획득`, 등급 색을 옅게 깐 바탕, 오른쪽에 그 레벨 견본 앞면의 위쪽만 잘라 보임)을 둔다. 칩 크기로는 카드가 안 읽히고
  빨강 칩은 상태 딱지로 읽혀 바꿨다. 보상은 펼친 단계의 이 줄에만 두고, 단계 제목 옆엔 칩을 붙이지 않는다.
  마스터는 공부할 단어 묶음이 아니라 복습으로 채워지는 기억 목표라 단계로 잇지 않는다 — 단계 선은 완곡에서 끝나고, 그 아래 같은 모양의 보상 줄
  (조건을 그대로 쓴다 — 완곡 전 `완곡 후, 단어의 90%를 장기기억 시`, 완곡 뒤 `단어의 90%를 장기기억 시 (지금 N%)`, 줄 높이는 단계 보상과 같게 한 줄 / `MASTER 카드 획득`, 마스터 하늘색 바탕, 받았으면 `받은 카드` / `MASTER 카드`)을 단계 목록 폭 전체로 둔다.
  완곡 전에도 흐리게 하지 않는다. 레벨 이름만 적으면 보상으로 읽히지 않아 '보상'이라고 쓴다.
  누르면 그 레벨 카드의 견본 전시(`RewardCardPreview`)가 뜬다. 카드 그래픽(기울기·광택·렌티큘러)·가사·뒷면은 상세와 똑같이 보여 줘야
  동기가 생기므로 손대지 않는다. 가사는 가장 많이 반복되는 줄(대개 후렴)과 그 다음 줄, 뒷면 단어는 중요도 상위 5개다.
  내 카드가 아니라는 건 카드 밖과 비어 있는 주인 정보로만 알린다 — 위 `견본` 표시, 편집·카드만 보기 없음, 점선 테 `획득 조건` 패널,
  앞뒷면 획득 순번·획득일 `—`(앞면 `— 번째 획득`), 빈 서명 칸. 레벨은 단계 응답(`/word-tiers`)에서 계산한다(앞에서부터 끝낸 단계 수, 마스터는 완곡 + 장기기억 90%).
- 곡 상세 `홈 | 단어 | 카드`, 아티스트 상세 `곡 | 카드` 탭: 카드 탭은 그곳에서 얻을 수 있는 카드 종류 전부를 늘어놓는다
  (`CardKindGrid`). 곡은 기본·BRONZE·SILVER·GOLD·MASTER(3열), 아티스트는 기본~DIAMOND 등급(2열)이고, 칸 아래에 종류 이름과
  조건 한 줄(단계 이름 / 마스터 곡 수)을 둔다. 받은 종류는 그 등급의 내 카드를 그리고 누르면 그 카드 상세로,
  아직인 종류는 견본을 그리고 이름 옆 점선 `견본` 표시를 붙여 누르면 견본 전시로 간다. 아티스트 카드 견본은 앞면 팬 순번·팬이 된 달을
  `—`로 비운다. 아티스트 상세의 곡 카드 도감은 없앴다 — 곡 카드는 곡 상세에서 본다.
  더미 카드는 id 가 없어 곡은 제목으로, 아티스트 카드는 이름으로 맞춘다.

## 프로필

`카드 | 학습` 탭. 카드 탭은 전시(아티스트 가로 스크롤 + 곡 카드 3열 그리드 — 상세와 같은 앞면을 기울기 효과 없이, 획득순(기본)/등급순/낡은순),
학습 탭은 기억한 단어 · 곡별 진도(장기/단기/남음) · 히트맵(연속 학습 상세 진입점만).

- 카드는 등급마다 따로지만 보관함은 곡·아티스트마다 한 칸이다. 가장 높은 등급 카드를 올리고, 여러 장이면 뒤에 카드 모서리 두 장을 겹쳐 그린다(숫자·연출 없음). 지난 등급 카드는 상세의 등급 패널에서 본다. 개수도 칸 수로 센다. `ArtistCardList` 도 같다.
- 곡 카드는 탭 안에서 전부 보인다(탭 자체가 모음이라 전체보기를 두지 않는다). 썸네일이 무거워 탭 전체를 가상화된 그리드로 그린다.
- 아티스트 가로 줄은 등급 높은 순(마스터 곡 수, 같으면 먼저 팬이 된 카드) 5장만 보이고, 헤더 `›` 로 `ArtistCardList`
  (카드가 폭을 다 차지하는 세로 목록, 등급순/획득순 — 획득순은 최근에 받은 카드부터)에 들어간다. 가로 줄 끝 `전체 보기` 도 같은 화면이다.

곡 카드를 누르면 `RewardCardDetail`, 아티스트 카드를 누르면 `ArtistCardDetail` 전시 화면 — 회전 센서(`useAnimatedSensor` ROTATION)로 폰 기울기의 35%만 반대로 돌고(화면 안 회전은 무시, 들고 있는 자세로 몇 초에 걸쳐 재정렬) 광택은 기울기를 1:1로 따라가며 드래그로 더 밀 수 있고,
탭하면 뒷면(가사·단어·획득 순번)이 나온다.
카드 아래 정보는 이것만 둔다(그 밖의 칩·안내는 넣지 않는다):
- 등급 패널 하나: 위에 등급 칩 줄(곡 기본~MASTER, 아티스트 기본~DIAMOND), 아래 고른 칩의 조건 한 줄. 얻은 칩은 등급 색, 다음 칩은 진행만큼 차고,
  아직 얻지 않은 칩(다음 칩과 그 위)을 고르면 조건 옆에 그 등급의 진행(`12 / 30`, 곡의 가장 높은 카드 기준), 얻은 칩이면 체크가 붙는다. 칩을 누르면 그 등급의 내 카드(순번·서명·가사·복습할 때가 된 단어 수가 각자 다르다)로
  바꿔 보여 주고 공유·가사 편집도 그 카드에 건다. 아직인 등급은 주인 정보를 비운 견본(새것)이고 공유·편집은 숨긴다.
  승급 조건과 견본 보기를 따로 두면 같은 '등급' 이야기가 두 곳에 흩어져 한눈에 안 들어와 합쳤다.
- 곡 카드: 상단 공유·카드만 보기·가사 편집 버튼(뒤집기는 카드 탭이 하므로 버튼이 없다), 복습할 때가 된 단어 N개 한 줄(낡는 기준은 낡음 설명 화면이 맡는다,
  견본을 보는 동안엔 흐리게), 등급 패널, 맨 아래 `곡 보기`(`SongDetail`)·`복습 시작하기`.
  조건은 "'따라 부르기' 단계 단어 모두 공부하기", MASTER 는 "곡 단어의 90%를 장기 기억으로 만들기". 단계 이름과 90% 는 앱에 두지 않고
  `GET /api/reward-cards` 의 `songGradeRule` 로 받는다(곡마다 같아 목록에 한 번). 진열장·획득 연출·곡 상세 카드 탭이 같은 문구 함수(`songGradeCondition`)를 쓴다.
  `복습 시작하기` 는 곡 덱(`/api/decks/by-song/{songId}`)의 due 복습을 바로 연다(`SongReview`, trigger `reward_card`).
  카드는 상단 버튼과 아래 정보를 뺀 남는 높이에 맞춰 그린다. 상단 `카드만 보기` 는 다른 UI·상태 표시줄을 숨기고 카드를 화면 가운데에
  크게 띄운다. 카드 밖을 누르거나 뒤로 가면 돌아온다.
- 아티스트 카드: 상단 공유 버튼, 등급 패널(조건 "이 아티스트 곡의 MASTER 카드 N장 모으기"), 맨 아래 `아티스트 보기`(`ArtistDetail`).
아티스트 카드 뒷면도 곡 카드처럼 마스터 곡 수 아래에 흰 서명 칸이 있다(위 '곡 카드 서명'). 크림 종이 몸체에선 흰 칸이 묻혀 옅은 테두리를 두른다.
마스터 카드는 앞면 구성부터 다르다 — 테 없이 앨범 아트를 끝까지 깔고, 글리터·무지개 광택이 두 장면 위를 함께 덮는다.
마스터 카드의 렌티큘러 장면 전환과 글리터는 Skia(`@shopify/react-native-skia`) 셰이더로 그린다 — 새 네이티브 빌드가 필요하고,
웹(개발용)은 SVG·띠 자르기로 흉내만 낸다.

## 서버 — 달성은 rating 트랜잭션, 발급은 서명

`domains:rewardcard`(`song_card`·`artist_card`·`reward_card_seq`, V45 → 등급별 발급 V46). 판정은 api 의 `RewardCardAchievementService` 가 rating 트랜잭션에서 `SongCardGrader`(domains:rewardcard)로 잰다.

- **출시 플래그 `reward-card`**(`FeatureFlagKeys.REWARD_CARD`, [feature-flag](../architecture/feature-flag.md)): 기존 API 에서 구클라에도 보이는 변경만 건다 —
  장기기억 기준 14일(꺼지면 7일, `LongTermThreshold`)과 rating 때 달성(꺼지면 `rewardCards` 가 비고 아무것도 쓰지 않는다). 새 `/api/reward-cards/**` 와 batch 채우기는 걸지 않는다(채우기는 늘 14일로 잰다).
- **언제 다는가**: rating 직후, 같은 트랜잭션에서. 복습 세션은 탭만 바꿔도 끝나 경계가 없으므로 세션 끝에 몰아 띄우지 않는다.
  카드는 곡마다 다섯 장뿐이고, 연속 학습 축하도 이미 rating 직후에 뜬다. 원인(방금 이 단어로 단계를 끝냄)과 결과가 붙어 있어야 읽힌다.
- **어느 경로에서**: `POST /api/flashcards/{id}/review` 와 곡의 첫 rating 인 `POST /api/songs/{id}/study-bootstrap` 둘 다. 응답의 `rewardCards[]` 를
  앱이 카드를 다시 받은 뒤 차례로 띄운다(`rewardCardStore.receiveReveals`, 한 번에 하나, 닫히면 다음). 앱을 열면 홈에서 한 번 `pending` 을 받아 같은 차례에 넣는다.
- **어느 곡을 재는가**: 방금 rating 한 단어가 담긴 곡 단어장의 곡들. 등급은 `/word-tiers` 응답 그대로 — 앞에서부터 끝낸 단계 수, 완곡 뒤 tier 단어 90% 장기기억이면 MASTER.
  잰 등급까지 아직 없는 등급의 카드를 낮은 등급부터 만든다. 담기지 않은 곡에 같은 단어가 있어 그 곡 단계가 끝나도, 그 곡 단어를 rating 할 때까지 카드는 나오지 않는다.
- **달성과 발급을 나눈다**: 행(`(user, song, grade)` 유일)이 생기면 달성(`created_at`, 순번 고정), `issued_at` 이 차면 발급(서명 확정).
  `issued_at` 이 NULL 이면 획득 연출이 남았다. 서명 전에 앱을 끄면 `GET /api/reward-cards/pending` 이 다음에 다시 준다. 서명 전에 다음 등급에 닿으면 두 카드가 차례로 뜬다.
- **순번**: 곡·아티스트의 등급별 "N번째 획득"은 `reward_card_seq` 의 `(kind, target_id, grade)` 행 하나를 `INSERT … ON DUPLICATE KEY UPDATE last_seq = LAST_INSERT_ID(last_seq + 1)` 로 올려 받는다.
  MAX()+1 은 REPEATABLE READ 에서 갭 락끼리 데드락이 난다. rating 과 같이 롤백되므로 빈 번호가 없다. 탈퇴는 soft delete 라 순번이 밀리지 않는다.
- **곡이 여럿일 때**: 곡·가사·유저 단어·flashcard 를 IN 으로 한 번씩 읽고 등급은 메모리에서 잰다. 쓰기는 (곡 id, 등급) 순으로 곡 카드를 다 한 뒤
  (아티스트 id, 등급) 순으로 아티스트 카드를 한다 — 순번 행 락이 늘 같은 순서로 잡혀야 카드 여러 장을 만드는 rating 끼리 데드락이 나지 않는다.
- **카드 전 기록 채우기**: batch `reward-card-backfill`(수동, suspend 된 CronJob)이 카드 기능 전부터 담아 둔 곡 단어장 전부를
  지금 등급까지 등급마다 곡 카드·아티스트 카드로 연출 없이 발급하고(서명은 빈 채로), 카드가 새로 생긴 유저에게 `reward_cards_backfilled` 푸시로 알린다(문구에 이름이 나온 곡 — 새 카드 중 등급이 가장 높고 같으면 나중에 담은 곡 — 의 카드 상세가 열리고, 닫으면 프로필 탭 카드 목록).
  안 그러면 담아 둔 곡이 많은 유저는 다른 곡과 겹치는 단어 하나를 rating 할 때마다 지금 공부하지 않는 곡의 카드가 새로 튀어나오고,
  한꺼번에 띄우면 prod 기준 1인 최대 36번의 연출이 몰린다.
  - 곡 단어장을 만든 순서대로 채워, 같은 곡·등급은 먼저 담은 유저가 앞 순번을 받는다. 탈퇴한 유저는 뺀다.
  - 끝에 모든 카드를 조용히 발급한다 — 구버전 앱으로 rating 해 쌓인 연출이 새 앱을 켜자마자 몰리지 않게. 그래서 새 앱이 충분히 퍼진 뒤 한 번만 돌린다
    (구버전 앱은 푸시를 눌러도 카드 화면이 없고, 다시 돌리면 그 사이 쌓인 연출이 사라진다). `--no-push` 는 채우기만 한다.
  - `--dry-run` 은 아무것도 쓰지 않고 새로 생길 곡·아티스트 카드 수, 사라질 연출 수, 푸시 받을 유저 수만 로그에 남긴다. CronJob 인자를 바꿔 돌린다:
    `kubectl create job --from=cronjob/reward-card-backfill rcb-dry-$(date +%s) -n <ns> --dry-run=client -o json | jq '.spec.template.spec.containers[0].args += ["--dry-run"]' | kubectl create -f -`
- **아티스트**: 곡 카드에 달성 때의 `songs.artist_id` 를 박제한다. 아티스트 연결(batch `artist-link`)이 늦으면 연결된 뒤의 rating 에서 이어 붙이고 그때 아티스트 카드가 생긴다.
  등급은 마스터 곡 수에서 구하되 카드로 남긴다 — 구간을 다시 맞춰도 받은 카드는 없어지지 않는다.

| API | |
|---|---|
| `POST /api/flashcards/{id}/review` | 응답 `rewardCards[]` = 이 rating 으로 새로 생긴 카드 `{kind: SONG\|ARTIST, cardId, targetId, grade, acquiredSeq}`, 곡(등급 순) → 아티스트 순 |
| `GET /api/reward-cards/pending` | 서명 전 카드 전부 |
| `GET /api/reward-cards` | 곡 카드 등급마다 한 장(최근 획득순, `id`·`issued`, 카드 면에 싣는 가사 줄·뒷면 단어 5개·`reviewedCount`/`dueCount`·곡의 다음 등급 진행 포함)·아티스트 카드 등급마다 한 장(마스터 순, 지난 등급은 다음 등급 전까지의 곡)·`songGradeRule {tierNames, masterPercent}` 한 번 |
| `POST /api/reward-cards/song-cards/{cardId}/issue` | `{signature: string[], lyricLineIndexes?: int[]}` 발급. 이미 발급이면 409 |
| `POST /api/reward-cards/artist-cards/{cardId}/issue` | `{signature}` |
| `PUT /api/reward-cards/song-cards/{cardId}/lyric` | `{lyricLineIndexes}` 1~2줄. 카드마다 따로다 |

- 가사 줄은 `/lyrics` 와 같은 모양이라 앱이 같은 방식으로 후리가나를 붙인다. 고르지 않았으면 서버가 기본 줄(가장 많이 반복되는 줄과 그 다음 줄)을 싣는다.
- `reviewedCount` 는 tier 단어 중 `last_review >= song_card.created_at` 인 카드 수, `dueCount` 는 그중 `due <= now` 인 수다(카드마다 받은 날이 달라 값도 다르다). 다음 등급 진행은 곡의 가장 높은 카드 기준 다음 단계의 공부한 단어 수,
  완곡 뒤엔 tier 단어 90%(올림)까지의 장기기억 수다.
- 카드 색(accent·ink)은 앱이 아트(곡 아트·아티스트 사진)에서 뽑는다(`artPalette`). accent 는 가장 선명하게 눈에 띄는 색조, ink 는 가장 넓게 깔린 색조이고, 밝기는 글씨가 읽히게 고정한다. 흑백 아트는 따뜻한 회색. 앱은 Skia, 웹은 canvas 로 픽셀을 읽고, 못 읽으면 id 로 고정 팔레트에서 고른다.

## 카드 공유

곡 카드·아티스트 카드를 인스타그램 스토리(카드 이미지)·X(링크)에 올려 앱 설치·진입을 늘린다.

- 링크는 `https://kotonoha.eastshine.dev/c/{token}`. 토큰은 `kind`·카드 id 를 서명한 JWT(HS256, 헤더 `kid`)이고 만료·발급 시각이 없어
  같은 카드는 늘 같은 링크다. DB 에 저장하지 않는다. 발급된(서명 끝난) 내 카드만 공유한다.
  서명 키는 `SHARE_TOKEN_KEYS`(`kid:secret` 쉼표 목록, 첫 키로 서명). 키를 버리면 올라간 링크가 전부 깨지므로 옛 키를 뒤에 남긴다.
- 링크는 카드의 지금 모습을 보여 준다. 주인 정보는 이름·프로필 사진만 내보낸다.
- `/c/{token}` 은 api 가 내려 주는 HTML 이다. X 크롤러는 JS 를 돌리지 않아 서버가 `og:*`·`twitter:card=summary_large_image` 를 채운다.
  api 는 share-web 의 `index.html` 을 받아 카드 메타와 화면 데이터(`<script id="kotonoha-share">` JSON)를 끼운다.
  share-web 은 app-rn 의 카드 컴포넌트를 웹으로 빌드한 것(`EXPO_PUBLIC_SHARE_WEB=1`, `src/shareWeb`)이라 앱과 같은 카드를 그린다.
  링크로 앱을 처음 알게 되는 사람에게 위는 축하(`{이름}님이 / 「{곡명}」 / 곡 카드를 얻었어요`, 곡명 줄은 18px 아래로 줄지 않고 꺾는다, 그 등급의 조건, 승급 계단).
  그 아래 같은 카드를 몇 번째로 얻었는지(`1,234번째로 얻은 카드예요`, 1번은 `처음으로`)를 숫자만 강조해 축하한다. 보는 사람은 앱을 모르므로 제목·조건에 등급 이름(MASTER 등)·앱 단계 이름('후렴 정복' 등)을 쓰지 않고
  무엇을 공부했는지('후렴에 나오는 단어를 모두', '7곡의 가사 단어를 완전히 외워야')로 적는다. 아래는 설치 유도(`shareHook` 훅·세 단계·내 기기 스토어를 앞에 둔 App Store·Google Play 배지)다.
  웹엔 `adjustsFontSizeToFit` 이 없어 문구는 줄마다 숨은 글자로 폭을 재 글자 크기를 줄이고(`FitText`), 말줄임·꺾임 없이 한 줄로 그린다.
  마스터 기준(%)이 필요해 `GET /api/reward-card-shares/{token}` 응답에 `songGradeRule` 을 싣는다.
  `앱에서 열기`(`kotonoha://c/{token}`)는 모바일에서만 머리줄에 둔다. 번들은 `/share-assets/**` 를 nginx 가 서빙한다.
  share-web 을 못 받으면 서버가 그린 간단한 페이지(미리보기 이미지·곡명·버튼)로 대신한다. 웹 카드 폰트는 Google Fonts 에서 받는다.
- 미리보기 이미지(og:image) 키는 `shares/{토큰 서명부}.png` 다. 서버 키 없이 만들 수 없어 카드 id 로 남의 미리보기 주소를 짐작할 수 없고,
  저장할 필요도 없다. 공개 도메인(`img.kotonoha.eastshine.dev`)으로 읽고, 다시 공유하면 덮어쓰며 객체에 `Cache-Control: max-age=300` 을 붙인다.
  없으면 곡·아티스트 아트워크.
- 앱은 카드 상세의 공유 버튼에서 `X 게시물로 공유`·`인스타그램 스토리로 공유`·`링크로 공유` 를 고른다. 화면의 카드 앞면을 정면으로 세워
  공유 시트를 열기 전에 화면에 보이는 그대로 한 번 떠서(Android 는 로컬 모듈 `modules/view-pixel-copy` 의 PixelCopy, iOS 는 Skia `makeImageFromView`)
  스토리 스티커와 1200×630 미리보기 이미지를 만든다. 뷰를 다시 그리는 캡처는 Android 에서 클립·투명도를 놓쳐 Skia 로 그린 층(뒷면 박 글자, 아티스트 사진)이 맨 위에 덧그려진다.
  스토리는 X 게시물 공유처럼 투명 바탕 흰 패널(머리줄 내 프로필 사진·이름·앱 아이콘, 가운데 카드, 바닥줄 왼쪽 훅·스토어 검색 안내, 오른쪽 `Kotonoha`·`노래로 배우는 일본어`)을
  스티커로 넘기고, 바탕은 카드 아트에서 뽑은 색(위 accent → 아래 ink) 그라데이션이다(안 넘기면 react-native-share 가 보라색을 깐다). 글자는 앱 UI 글꼴(Funnel Sans, 한글은 시스템 고딕)이다.
  세 공유 모두 받은 사람을 부르는 훅(`나도 최애곡 카드 만들러 가기`·`나도 최애 아티스트 카드 만들러 가기`, `shareHook`)을 넣는다 — 스티커 바닥줄, X·링크 글 가운데 줄.
  X·링크 글은 `{이름}님이 「제목」 곡 카드를 얻었어요!` / 훅 👉 링크 / `노래로 배우는 일본어, 코토노하` 세 덩어리를 빈 줄로 띄운다(`shareText`). X intent 의 `url` 은 글 맨 끝에 붙어 링크를 글 안에 넣는다.
  미리보기만 서버에 올린다 — X 큰 카드는 약 1.91:1 로 잘라서 세로 이미지를 쓰면 카드 가운데만 보인다.
  - X: 미리보기가 올라간 뒤 `x.com/intent/post` 글쓰기 화면을 연다. 글 맨 위에 `#코토노하` 해시태그를 단다(`xShareText`). 이미지는 첨부하지 않고 링크 미리보기로 붙는다.
  - 인스타 스토리: 패널을 스티커(`stickerImage`)로 얹어 스토리 편집 화면을 바로 연다(`react-native-share`, iOS `instagram-stories://`·Android `ADD_TO_STORY`).
    Meta 앱 id 는 공개 값이라 `instagramStory.native.ts` 의 `FACEBOOK_APP_ID` 에 둔다. 링크 스티커 키도 넘기지만 인스타가 받아 줄지는 보장되지 않는다.
  - 인스타 DM: 링크 공유와 같은 글로 DM 보내기 화면을 연다(`shareToInstagramDirect`). iOS 는 비공식 `instagram://sharesheet?text=`,
    Android 는 인스타 패키지로 보내는 text/plain 이다. 카드 그림은 DM 의 링크 미리보기에 맡긴다.
  - 링크: 미리보기가 올라간 뒤 OS 공유 시트로 링크를 낸다.
- 획득 화면 마지막(서명 뒤 순번이 다 오른 장면)에 `친구에게 자랑하기` CTA 가 같은 공유 메뉴를 연다. 서버에 발급된 카드에만 뜨고, 확인·다음은 그 아래 보조 버튼이 된다.
- 링크를 받은 앱은 `SharedCard` 화면(남의 카드 보기 전용, 곡·아티스트 보기 버튼)을 연다. 로그인 전이면 로그인·가입 뒤에 연다.
- 디퍼드 딥링크(설치 뒤 첫 실행에 그 카드로 보내기)는 일부러 하지 않는다. 미설치자는 랜딩 → 스토어까지다.
- Universal Links·Android App Links 는 `/.well-known/apple-app-site-association`·`/.well-known/assetlinks.json` 이 검증한다.
  `SHARE_APPLE_APP_ID`·`SHARE_ANDROID_SHA256_FINGERPRINTS` 를 채우기 전엔 둘 다 404 라 https 링크는 랜딩으로만 열린다.

| API | |
|---|---|
| `PUT /api/reward-cards/{song-cards\|artist-cards}/{cardId}/share` | `{imageUploaded?}` → `{token, url}`. `imageUploaded` 면 올라간 미리보기를 HEAD 로 확인(≤5MB png), 어긋나면 지운다 |
| `POST /api/reward-cards/{song-cards\|artist-cards}/{cardId}/share/image-upload-url` | → `{uploadUrl, headers, expiresAt}`. png presigned PUT, 키는 링크에서 나온다 |
| `GET /api/reward-card-shares/{token}` | 앱의 `SharedCard` 화면. `{token, url, kind, songCard?, artistCard?, owner: {name, profileImageUrl}, songGradeRule}`, 카드 모양은 `GET /api/reward-cards` 와 같다 |
