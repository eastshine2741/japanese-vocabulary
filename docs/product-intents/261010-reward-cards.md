# 보상 카드 (곡 카드 · 아티스트 카드)

Pen `app-rn/japanese-vocabulary.pen` 의 `P3a. Profile — 카드 탭` / `P3b. Profile — 학습 탭`,
`component/songCard` · `component/artistCard`, `spec/songCard states` 가 원본이다.
앱은 서버 카드(`GET /api/reward-cards`)를 그린다. 개발 빌드에선 화면 왼쪽 위 `카드: 서버|더미` 칩으로 더미 데이터
(`app-rn/src/components/rewardCards/dummyRewardCards.ts`, 모든 등급·재질 견본)로 바꿔 볼 수 있다. 더미를 보는 동안엔 서버 연출을 띄우지 않는다(서버에 남아 나중에 뜬다).

## 곡 카드 — 한 곡에 한 장, 한 방향으로만 오른다

| 등급 | 조건 | 카드 |
|---|---|---|
| 기본 | 곡 단어를 하나라도 공부 (첫 rating) | 무광 종이 `◇◇◇` |
| BRONZE | 후렴 정복 단계 단어를 전부 공부 (남음 0) | 동 테 · 동박 제목 `◆◇◇` |
| SILVER | 따라 부르기 단계 단어를 전부 공부 | 은 테 · 은박 제목·세로 가사 `◆◆◇` |
| GOLD | 완곡 단계 단어를 전부 공부 | 금 테 · 금박 제목·세로 가사 · 아트 홀로·글리터 `◆◆◆` |
| MASTER | 곡 단어의 **90%** 가 장기기억 (`stability >= 14`) | 마스터 카드 (렌티큘러 인쇄 앞면) |

- 재질과 이름은 아티스트 카드(종이 → 동 → 은 → 금)와 같다. 마스터는 아티스트의 PLATINUM·DIAMOND 와 섞이지 않게 MASTER 로 따로 둔다.
  두 사다리는 이어지지 않는다 — 아티스트 재질은 마스터 곡 수로만 오른다.
- 등급 차이는 테에 힘을 주지 않고 박이 차지하는 자리(제목 → 세로 가사 → 아트 전체)로 낸다. 뒷면에는 테가 없어서,
  뒷면 몸체를 앞면 테와 같은 재질로 칠해 앞뒤를 잇는다 (마스터 뒷면은 곡 색 몸체).

마스터 카드의 렌티큘러 앞면은 그림 두 장(앞면 ↔ 장면 B)뿐이라 단계마다 줄 수 없다. 레벨마다 주면 레벨이 오르는 순간
범위가 넓어져 마스터가 꺼지고, 한 번 준 마스터를 유지하면 다음 단계를 공부할 이유가 사라진다.
그래서 완곡 다음의 마지막 보상 하나로 둔다. 어느 시점이든 다음 목표는 하나다.

마스터를 '전부'가 아니라 90% 로 두는 건, 정직하게 공부해도 due 마다 약 10% 는 잊혀 stability 가 떨어지기 때문이다.
'전부'는 곡 단어가 많을수록 모두 동시에 넘는 날이 드물어져 반년 넘게 걸리고 곡마다 들쭉날쭉하다. prod 곡 단어 수
(중앙값 78, p10~p90 48~124)로 시뮬레이션하면 90% 는 곡 길이와 상관없이 약 6주다.

## 낡음 — 기억 확률(R)로 잰다

```
recall = 평균(R_i)   // 곡의 tier 단어 중 카드를 받은 뒤 리뷰한 단어, FSRS retrievability. 없으면 1
age    = clamp((0.9 − recall) / 0.4, 0, 1)
```

- 장기기억 비율이 아니라 R 이다. 새 단계를 막 시작한 단어는 R 이 높아 카드가 낡아 보이지 않는다.
- 등급과 상관없이 곡의 tier 단어 전부로 잰다. 단어 기억은 곡마다가 아니라 하나라서, 받기 전 리뷰까지 세면 다른 곡에서 공부하고
  밀린 단어 때문에 받자마자 낡은 카드가 나온다. 그래서 받은 뒤 리뷰한 단어만 센다 — 받는 순간은 새것이다.
- 0.9 는 FSRS 목표 기억률이라, due 를 매일 치우면 카드는 낡지 않는다.
- 구간: 새것 ≥ 0.9 · 빛바램 ≥ 0.8 · 낡음 ≥ 0.65 · 너덜너덜. 코팅 `(1 − age)^1.6` 이 포일·반사광·금속 테 명암을 함께 줄여, 끝엔 무광 종이만 남는다.
- 레벨·마스터는 저장하는 이벤트, 낡음은 조회 때 계산한다.
- 손상은 age 가 오를수록 차례로 붙는다: 빛바램·잔흠집(기울이면 빛을 받음) → 모서리가 하얗게 닳고 얼룩·가로 접힘
  → 모서리 접힘·세로 접힘·코팅이 벗겨져 판지가 드러남 → 찢어져 누런 테이프로 붙인 자국. 카드 id 시드라 늘 같은 자리다
  (`wearGeometry.ts`, 질감은 `app-rn/assets/cards/`).

## 곡 카드 가사 — 주인이 고른다

- 앞면 세로쓰기와 뒷면(후리가나·번역)에 싣는 가사는 주인이 곡 전체에서 1~2줄 고른다. 공부한 단계로 제한하지 않는다.
- 카드를 처음 얻는 순간 전체 화면 획득 연출(`RewardCardReveal` 화면)이 뜨고, 거기서 `가사 고르기` 로 바로 고르거나
  `이대로 받기` 로 기본 줄을 그대로 받는다. 연속 학습 축하처럼 조건이 채워지면 스스로 뜨며(`rewardCardStore.reveal` →
  `RewardCardRevealHost` 가 화면을 연다), 축하 화면이 떠 있으면 그게 닫힌 뒤에 뜬다. 오버레이가 아니라 스택 화면인 건 아래 화면이
  매 프레임 다시 합성되어 카드 효과가 끊기기 때문이다.
- 획득 화면 첫 단계엔 칩·곡명·아티스트명을 두지 않는다(카드에 이미 있다). 대신 카드 위에 '곡 카드를 얻었어요' 한 줄,
  아래에 이 카드가 무엇인지 두 줄과 승급 계단(기본·BRONZE·SILVER·GOLD·MASTER, 각 조건 = 단계 이름)을 두고 지금 자리를 짚는다.
  따로 튜토리얼 없이 처음 받는 순간에 규칙을 알게 하려는 것이다. 아티스트 카드는 같은 자리에 재질 계단(기본~DIAMOND, 마스터 곡 수)을 둔다.
- 낡음은 첫 곡 카드를 받을 때 서명 뒤 화면 하나(`CardWearIntro`)로 한 번만 설명한다. 방금 받은 카드 아래 기억할 확률 슬라이더
  (95% → 50%, 90% 눈금)가 들어오자마자 저절로 왼쪽에서 오른쪽으로 움직여 카드가 낡아 가는 걸 보여 주고, 끌어서 직접 볼 수도 있다.
  구간 이름은 쓰지 않고 '기억할 확률: 이 곡에서 공부한 단어를 지금 떠올릴 수 있는 확률의 평균(평균 R), 시간이 지나면 떨어지고 복습하면 오름, 90% 아래부터 낡음' 세 줄만 적는다. 본 적이 있는지는 아직 메모리에만 있어 앱을 다시 켜면 다시 뜬다.
  개발 빌드에선 곡 카드 상세의 `기억할 확률` 줄을 길게 누르면 이 화면만 바로 뜬다(본 것으로 치지 않는다).
- 나중에도 카드 상세의 편집 버튼(`RewardCardLyricEdit`)에서 언제든 바꾼다. 고르는 대로 미리보기 앞면이 바뀌고, 2줄이 찬 채로
  새 줄을 누르면 먼저 고른 줄이 빠진다.
- 개발 빌드에선 프로필 곡 카드·아티스트 카드를 길게 눌러 획득 화면을 다시 띄운다. 이렇게 띄운 연출의 서명·가사는 서버에 보내지 않는다.

## 곡 카드 서명 — 발급 때 한 번

- 곡 카드 뒷면엔 실물 카드처럼 흰 서명 칸이 있고, 주인이 손으로 그린 서명이 그대로 들어간다.
- 서명은 카드마다 발급 때 한 번만 받고 고칠 수 없다. 획득 화면은 가사를 고르든 그대로 받든 마지막에 서명 단계를 거쳐야 닫히고,
  첫 단계에서 뒤로 가기도 막는다. 도는 동안 보이는 뒷면 서명 칸은 비어 있다.
- 패드와 카드 서명 칸은 같은 3:1 좌표(`SIGNATURE_BOX`)를 써서, 패드에 쓴 그대로 칸에 줄어 들어간다. 긋는 동안 미리보기 카드 칸도 점마다 따라 그린다.
- 서명은 '이 카드는 내 것'이라는 감각을 만드는 의식이다. 서명 단계에선 뒷면 빈 칸을 강조색 점선으로 짚는다(패드는 빈 종이다 —
  ✕·밑줄은 뜻이 전해지지 않아 뺐다). 그리는 대로 뒷면 미리보기 칸에 서명이 들어가고, 확정하면 그 서명된 뒷면 그대로 카드가 앞면으로 돌아선 뒤
  '카드를 획득했어요!'와 '이 곡의 카드를 전체 유저 중 N번째로 획득했어요'가 붙는다(발급일은 넣지 않는다). 서명을 확정한 뒤엔 뒤로 갈 수 없다.
- 획득 연출: 큰 봉투가 찢는 띠를 화면 한가운데에 두고 아래 끝은 화면 밖으로 걸친 채 떠오르고 '옆으로 밀어서 뜯기'를 띄운다 — 유저가 윗띠를 밀어 뜯어야(눌러도 뜯긴다) 공개가 시작된다.
  봉투는 카드 색으로 물들고 뒷날개 접힘·절취선이 있다. 카드는 다 뜯기 전엔 그리지 않는다. 손가락이 지나간 자리(x·y)대로 찢기고 찢긴 조각은 손가락 자리를 축으로 들리며, 칸마다 진동, 다 뜯으면 조각이 날아가고 0.3초 숨을 모은다(방이 어두워지고 봉투가 부풀며 찢긴 틈으로 빛이 새고, 진동이 두두두 점점 빠르고 세게). 이어 화면이 한순간 하얗게 날아가며 무거운 두 방. 카드는 1.8초에 걸쳐 봉투에서 화면 가운데로 떠오르며 커지고, 세로축으로 일곱 바퀴(처음 초당 12바퀴) 점점 느려지게 돌아 앞면에서 멈춘다(옆면이 지날 때마다 진동이라 진동도 빠르다가 느려진다, 끝 무렵 조금 세게). 봉투는 아래로 떨어진다. 튕기는 바운스는 쓰지 않는다. 살짝 넘치게 커졌다가 제자리에 박히는 순간 한 번 더 번쩍이고 무거운 두 방+성공 진동·폭죽, 그 뒤에 문구가 올라온다.
  뒷면에도 내용이 있어 엎어 뒀다 뒤집는 공개는 쓰지 않는다(도는 동안엔 뒷면도 비친다). 승급 계단은 지금 자리까지 한 칸씩 차오른다(칸마다 가벼운 진동).
- 최종 지급: 서명된 뒷면을 잠깐 보여 준 뒤 화면이 번쩍이며 무거운 두 방과 함께 앞면으로 한 번 뒤집힌다(여러 바퀴 돌리지 않는다 — 봉투 연출과 겹친다).
  이어 'N번째' 가 0 부터 올라가며 살짝 커지다가(바뀔 때마다 틱) 멈추며 제 크기로 돌아오고 무거운 두 방+성공 진동. 그 뒤 확인 버튼이 눌린다.
- 햅틱(`expo-haptics`, 새 네이티브 빌드 필요): 위 연출, 서명을 확정할 때 가볍게.
- 서명 없이 발급된 카드(더미, 아래 '카드 전 기록 채우기')는 칸에 표시 이름을 대신 찍는다. 나중에 서명하게 하지 않는다 —
  서명은 따낸 순간을 내 카드로 확정하는 동작이라, 이룬 순간 없이 받은 카드에 서명을 요구하면 할 일 목록처럼 귀찮기만 하다.
- 아티스트 카드도 같은 획득 화면(`RewardCardReveal`, `kind: 'artist'`)으로 받는다. 고를 가사가 없어 `서명하기` 하나로 바로 서명 단계에 가고,
  나머지(뒤로 가기 막기·서명 칸 점선·앞면으로 돌아서며 '이 아티스트의 카드를 전체 유저 중 N번째로 획득했어요')는 곡 카드와 같다.


## 등급 오름 — 오른 이유를 박으면 새 재질이 번진다

- 이미 가진 카드의 등급이 오르면(곡 카드 레벨·마스터, 아티스트 카드 재질) 봉투도 서명도 없다. 봉투는 '안에 뭐가 들었나'의 재미라
  같은 카드가 바뀌는 순간과 맞지 않고, 서명이 남은 카드가 봉투에서 다시 나오면 새 카드로 읽힌다. 마스터도 같은 연출이다.
- 문질러 벗기기는 거절했다 — 마스터가 아니면 앞면 차이가 테 색 정도라 벗겨도 바뀐 게 안 보인다. 대신 등급이 오른 이유를 짚는다.
- 한 단계 아래 재질의 같은 카드를 잠깐 다 보여 준 뒤, 새로 찰 자리로 2.4배 다가간다(곡 카드는 새 레벨 다이아, 마스터는 다이아 줄,
  아티스트 카드는 오른쪽 위 재질 각인). 그 자리만 밝게 남기고 둘레를 어둡게 누르며, 그 자리에서 파동이 퍼진다. 파동마다
  두-근 진동(네 번까지)과 '눌러서 새기기'. 누르면 카드가 밀려 들어가고 둘레가 더 어두워지며 빛이 모이고(간격이 좁아지며 세지는 연타, 내리치기 직전 한 박자 멈춤), 쾅 박히며 카드가 반동으로
  튀고 자국이 크게 튀어나왔다 자리 잡는다. 두 겹 충격파·번쩍임·무거운 연타 한 덩어리와 사이를 둔 여진. 박힌 자리에서 새 재질이 원으로 번져 카드 전체를 덮는다 — 빛나는 테두리가 앞장서고
  잔물결 둘이 따르며, 막 덮인 자리에 광택이 지나간다. 진동은 처음엔 두 겹으로 촘촘하고 세다 띄엄띄엄. 그동안 화면이 물러나 카드 전체가 보인다.
  다 덮으면 카드가 한 번 부풀며 연타+한 방+성공 진동, '{재질} 카드로 강화되었어요!', 승급 계단이 옛 칸에서 한 칸 오르고 확인 버튼.
  계단은 다가가는 동안 숨는다. 누른 뒤 다 덮기까지 약 3.2초.
- 두 면을 Skia 로 이미지로 떠서 번지는 원을 마스크로 쓴다(웹은 겹쳐 비추기만). 박힐 자리는 앞면 배치에서 계산한다
  (`songUpgradeFocus`·`artistUpgradeFocus`) — 앞면 배치를 바꾸면 같이 고친다. `rewardCardStore.upgradeCard` 가 획득 화면과 같은
  자리(`RewardCardReveal` 라우트, `upgrade: true`)로 띄운다. 옛 재질은 서버 연출이면 오르기 전 등급(`seenGrade`)으로, 개발용으로 띄우면 지금 재질에서 한 단계 거꾸로 만든다(`cardUpgrade.ts`),
  개발 빌드에선 프로필 카드를 길게 눌러 '등급 오르기'를 고른다.

## 아티스트 카드

'나는 이 아티스트의 팬이다'를 보여 주는 카드다. 곡 카드보다 오래 걸려야 하고, 곡을 더 많이 공부할수록 오른다.

- 그 아티스트의 첫 곡 카드와 함께 종이 카드로 발급된다.
- 기준은 하나, 그 아티스트의 **마스터 곡 카드 수** 다. 이 숫자는 상한 없이 카드에 새겨진다.
- 재질은 숫자가 구간에 닿을 때만 바뀐다. 납찰(納札)처럼 위로 갈수록 구간이 넓어서, 곡이 적은 아티스트도 아래 몇 단계는
  금방 거치고 곡이 많은 아티스트의 팬에게도 위가 남는다. 최고 재질 뒤에도 숫자는 계속 오른다.

| 재질 | 마스터 곡 | 앞면 사진 마감 | 앞면 인증 스티커·빛 | 뒷면 몸체 |
|---|---|---|---|---|
| 종이 | 0 | 무광 인화 (검정이 살짝 뜨고 종이 결) | 붉은 잉크 도장 | 크림 종이 |
| 동 | 1 | 반광 | 동 박 스티커, 빛줄기 + 에칭 | 짙은 초콜릿 + 구리 박 숫자 |
| 은 | 3 | 반광, 대비 조금 더 | 은박 스티커, 빛줄기 + 에칭 | 흑연 + 은박 숫자 |
| 금 | 7 | 유광 (깊은 검정) | 금박 스티커, 글리터 | 검정 + 금박 숫자 |
| 플래티넘 | 15 | 유광 + 더 선명 | 백금 홀로그램 스티커, 글리터 + 은은한 홀로 (무지개 없음) | 밝은 헤어라인 백금 |
| 다이아 | 30 | 유광 + 가장 선명 | 무지개 결정 홀로그램 스티커, 결정면·흰 섬광·무지개 | 투명한 결정면 + 섬광·무지개 |

- 곡 카드(수집 카드)와 달리 회원 카드다. 앞뒷면 모두 테·띠가 없다. 사진 색은 모든 재질이 원본 그대로이고, 재질은 인화 마감
  (`artistPhotoTone.ts`, 대비와 검정이 뜨는 정도만 바꿈. 앱은 Skia ColorMatrix·웹은 CSS 필터)과 그 위의 빛으로만 오른다.
  채도를 깎거나 금속 색을 사진에 덧칠하면 바래거나 누렇게 보여 종이보다 못해진다. 컬러 사진 위 이름에 금속박을 쓰면 색끼리
  부딪혀서 이름은 늘 흰 글씨이고, 박(`FoilText`)은 작은 재질 각인과 뒷면 숫자에만 쓴다. 뒷면은 재질로 만든 몸체이고,
  실제 멤버십 카드처럼 동·은·금은 깊은 색 몸체에 박을 찍는다.
- 앞면 재질은 멤버십 카드 귀퉁이의 정품 인증 홀로그램처럼, 그 재질로 만든 인증 스티커(`CardSeal`)로 보인다. 오른쪽 위에
  두고 `言の葉` 글자를 볼록하게 찍는다. 기울이면 빛 띠가 지나가고 글자 모서리에 빛이 맺힌다. 종이는 붉은 잉크 도장이다.
  IC 칩은 결제 기능이 없어 어색하고, 기념 디스크는 작으면 동전 같고 크게 빼면 사진을 가리고 끝만 비치면 레코드로 안 읽혀 거절했다. 글씨는 왼쪽에 모은다: 위에 몇 번째 팬, 아래에 이름과 그 밑 한 줄(팬이 된 달 · 재질 각인). 빛 효과는 기울일 때만 보이면 썸네일에서 등급이 안 갈려서,
  썸네일은 재질만큼 멈춘 빛(에칭·반짝임 몇 점·홀로·결정면)을 그리고, 상세 화면은 가만히 있어도 빛이 천천히 흔들린다.
- 다이아는 결정면(`FacetLayer`, 기울이면 면이 번갈아 빛남)과 흰 섬광이 바탕이고, 무지개는 그 위에 얹는다. 무지개만 있으면 다이아가 아니라 무지개로 읽힌다.
- 몇 번째 팬·팬이 된 날(첫 곡 카드 날)은 발급 때 고정된다. 카드가 바뀌는 건 마스터 곡이 늘 때뿐이다.
- 낡음은 없다. 마스터는 되돌리지 않는 이벤트이고 재질은 그 수에서 계산한다 (`artistGrade.ts`).
- 앞면은 팬 정보다. 몇 번째 팬, 팬이 된 달, 아티스트 이름, 재질 이름 각인(종이는 없음)을 왼쪽에 둔다.
  마스터 곡 수는 뒷면에만 있다.
- 뒷면은 마스터 곡 수, 소유자 칸, 최근 마스터한 곡 5개(마스터 순번·제목, 나머지는 '외 N곡')다. 다음 재질까지의 진행은 카드에 넣지 않는다.
  앨범 커버는 곡이 아니라 앨범마다 달라 곡을 가르지 못하므로 제목 옆 작은 곁들임으로만 쓴다.
- 구간 값은 마스터 한 곡에 실제로 걸리는 기간을 보고 다시 맞춘다. 얻은 재질은 내리지 않는다.

## 곡 상세·아티스트 상세에서 카드 알리기

카드는 학습의 결과라 학습 데이터보다 앞세우지 않는다.

- 곡 상세 `완곡까지 3단계`: 펼친 단계가 아직 못 받은 카드면 진행 막대와 학습 버튼 사이에 `단계 완료 보상` 줄
  (`BRONZE 카드 획득`, 재질 색을 옅게 깐 바탕, 오른쪽에 그 레벨 견본 앞면의 위쪽만 잘라 보임)을 둔다. 칩 크기로는 카드가 안 읽히고
  빨강 칩은 상태 딱지로 읽혀 바꿨다. 보상은 펼친 단계의 이 줄에만 두고, 단계 제목 옆엔 칩을 붙이지 않는다.
  마스터는 공부할 단어 묶음이 아니라 복습으로 채워지는 기억 목표라 단계로 잇지 않는다 — 단계 선은 완곡에서 끝나고, 그 아래 같은 모양의 보상 줄
  (조건을 그대로 쓴다 — 완곡 전 `완곡 후, 단어의 90%를 장기기억 시`, 완곡 뒤 `단어의 90%를 장기기억 시 (지금 N%)`, 줄 높이는 단계 보상과 같게 한 줄 / `MASTER 카드 획득`, 마스터 하늘색 바탕, 받았으면 `받은 카드` / `MASTER 카드`)을 단계 목록 폭 전체로 둔다.
  완곡 전에도 흐리게 하지 않는다. 레벨 이름만 적으면 보상으로 읽히지 않아 '보상'이라고 쓴다.
  누르면 그 레벨 카드의 견본 전시(`RewardCardPreview`)가 뜬다. 카드 그래픽(기울기·광택·렌티큘러)·가사·뒷면은 상세와 똑같이 보여 줘야
  동기가 생기므로 손대지 않는다. 가사는 가장 많이 반복되는 줄(대개 후렴)과 그 다음 줄, 뒷면 단어는 중요도 상위 5개다.
  내 카드가 아니라는 건 카드 밖과 비어 있는 주인 정보로만 알린다 — 위 `견본` 표시, 편집·카드만 보기 없음, 점선 테 `획득 조건` 패널,
  앞뒷면 획득 순번·획득일 `—`(앞면 `— 번째 획득`), 빈 서명 칸. 레벨은 단계 응답(`/word-tiers`)에서 계산한다(앞에서부터 끝낸 단계 수, 마스터는 완곡 + 장기기억 90%).
- 곡 상세 `홈 | 단어 | 카드`, 아티스트 상세 `곡 | 카드` 탭: 카드 탭은 그곳에서 얻을 수 있는 카드 종류 전부를 늘어놓는다
  (`CardKindGrid`). 곡은 기본·BRONZE·SILVER·GOLD·MASTER(3열), 아티스트는 기본~DIAMOND 재질(2열)이고, 칸 아래에 종류 이름과
  조건 한 줄(단계 이름 / 마스터 곡 수)을 둔다. 얻은 종류는 내 카드를 그 종류로 돌려 그리고(지나온 레벨·재질) 누르면 내 카드 상세로,
  아직인 종류는 견본을 그리고 이름 옆 점선 `견본` 표시를 붙여 누르면 견본 전시로 간다. 아티스트 카드 견본은 앞면 팬 순번·팬이 된 달을
  `—`로 비운다. 아티스트 상세의 곡 카드 도감은 없앴다 — 곡 카드는 곡 상세에서 본다.
  아직 더미 카드라 곡은 제목으로, 아티스트 카드는 이름으로 맞춘다.

## 프로필

`카드 | 학습` 탭. 카드 탭은 전시(아티스트 가로 스크롤 + 곡 카드 3열 그리드 — 상세와 같은 앞면을 기울기 효과 없이, 등급순/획득순/낡은순),
학습 탭은 기억한 단어 · 곡별 진도(장기/단기/남음) · 히트맵(연속 학습 상세 진입점만).

- 곡 카드는 탭 안에서 전부 보인다(탭 자체가 모음이라 전체보기를 두지 않는다). 썸네일이 무거워 탭 전체를 가상화된 그리드로 그린다.
- 아티스트 가로 줄은 재질 높은 순(마스터 곡 수, 같으면 먼저 팬이 된 카드) 5장만 보이고, 헤더 `›` 로 `ArtistCardList`
  (카드가 폭을 다 차지하는 세로 목록, 등급순/획득순 — 획득순은 최근에 받은 카드부터)에 들어간다. 가로 줄 끝 `전체 보기` 도 같은 화면이다.

곡 카드를 누르면 `RewardCardDetail`, 아티스트 카드를 누르면 `ArtistCardDetail` 전시 화면 — 회전 센서(`useAnimatedSensor` ROTATION)로 폰 기울기의 35%만 반대로 돌고(화면 안 회전은 무시, 들고 있는 자세로 몇 초에 걸쳐 재정렬) 광택은 기울기를 1:1로 따라가며 드래그로 더 밀 수 있고,
탭하면 뒷면(가사·단어·획득 순번)이 나온다.
카드 아래 정보는 이것만 둔다(그 밖의 칩·안내는 넣지 않는다):
- 곡 카드: 상단 편집·뒤집기 버튼, 레벨(`레벨 1~3`·`마스터` — 단계 이름을 레벨 이름으로 쓰지 않는다)과 그 옆 곡 제목 칩(누르면 `SongDetail`), 기억할 확률 %와 그 산정 기준 한 줄('남은 기억'은 뜻이 안 읽혀 바꿨다),
  다음 레벨 승급 조건("'따라 부르기' 단계 단어 모두 공부하기" · 레벨 3 은 "곡 단어의 90%를 장기 기억으로 만들기")과 진행.
  맨 아래 `복습 시작하기` 는 곡 덱(`/api/decks/by-song/{songId}`)의 due 복습을 바로 연다(`SongReview`, trigger `reward_card`).
  카드는 상단 버튼과 아래 정보를 뺀 남는 높이에 맞춰 그린다. 상단 `카드만 보기` 는 다른 UI·상태 표시줄을 숨기고 카드를 화면 가운데에
  크게 띄운다. 카드 밖을 누르거나 뒤로 가면 돌아온다.
- 아티스트 카드: 상단 뒤집기 버튼, 재질(`기본`·`BRONZE`·`SILVER`·`GOLD`·`PLATINUM`·`DIAMOND`)과 그 옆 아티스트 이름 칩(누르면 `ArtistDetail`),
  다음 재질 승급 조건("이 아티스트의 마스터 곡 카드 N장 모으기")과 진행.
아티스트 카드 뒷면도 곡 카드처럼 마스터 곡 수 아래에 흰 서명 칸이 있다(위 '곡 카드 서명'). 크림 종이 몸체에선 흰 칸이 묻혀 옅은 테두리를 두른다.
마스터 카드는 앞면 구성부터 다르다 — 테 없이 앨범 아트를 끝까지 깔고, 글리터·무지개 광택이 두 장면 위를 함께 덮는다.
마스터 카드의 렌티큘러 장면 전환과 글리터는 Skia(`@shopify/react-native-skia`) 셰이더로 그린다 — 새 네이티브 빌드가 필요하고,
웹(개발용)은 SVG·띠 자르기로 흉내만 낸다.

## 서버 — 달성은 rating 트랜잭션, 발급은 서명

`domains:rewardcard`(`song_card`·`artist_card`·`reward_card_seq`, V43). 판정은 api 의 `RewardCardAchievementService` 가 rating 트랜잭션에서 `SongCardGrader`(domains:rewardcard)로 잰다.

- **언제 다는가**: rating 직후, 같은 트랜잭션에서. 복습 세션은 탭만 바꿔도 끝나 경계가 없으므로 세션 끝에 몰아 띄우지 않는다.
  카드 이벤트는 곡마다 다섯 번뿐이고, 연속 학습 축하도 이미 rating 직후에 뜬다. 원인(방금 이 단어로 단계를 끝냄)과 결과가 붙어 있어야 읽힌다.
- **어느 경로에서**: `POST /api/flashcards/{id}/review` 와 곡의 첫 rating 인 `POST /api/songs/{id}/study-bootstrap` 둘 다. 응답의 `rewardCards[]` 를
  앱이 카드를 다시 받은 뒤 차례로 띄운다(`rewardCardStore.receiveReveals`, 한 번에 하나, 닫히면 다음). 앱을 열면 홈에서 한 번 `pending` 을 받아 같은 차례에 넣는다.
- **어느 곡을 재는가**: 방금 rating 한 단어가 담긴 곡 단어장의 곡들. 등급은 `/word-tiers` 응답 그대로 — 앞에서부터 끝낸 단계 수, 완곡 뒤 tier 단어 90% 장기기억이면 MASTER.
  담기지 않은 곡에 같은 단어가 있어 그 곡 단계가 끝나도, 그 곡 단어를 rating 할 때까지 카드는 오르지 않는다.
- **달성과 발급을 나눈다**: 행이 생기면 달성(`created_at`, 순번 고정), `seen_grade` 가 차면 발급(서명 확정). `seen_grade` 가 NULL 이면 획득 연출이,
  `grade` 와 다르면 등급 오름 연출이 남았다. 서명 전에 앱을 끄면 `GET /api/reward-cards/pending` 이 다음에 다시 준다. 서명 전에 더 오르면 오른 등급으로 받는다.
- **순번**: 곡·아티스트별 "N번째 획득"은 `reward_card_seq` 행 하나를 `INSERT … ON DUPLICATE KEY UPDATE last_seq = LAST_INSERT_ID(last_seq + 1)` 로 올려 받는다.
  MAX()+1 은 REPEATABLE READ 에서 갭 락끼리 데드락이 난다. rating 과 같이 롤백되므로 빈 번호가 없다. 탈퇴는 soft delete 라 순번이 밀리지 않는다.
- **곡이 여럿일 때**: 곡·가사·유저 단어·flashcard 를 IN 으로 한 번씩 읽고 등급은 메모리에서 잰다. 쓰기는 곡 id 순으로 곡 카드를 다 한 뒤
  아티스트 id 순으로 아티스트 카드를 한다 — 순번 행 락이 늘 같은 순서로 잡혀야 카드 여러 장을 만드는 rating 끼리 데드락이 나지 않는다.
- **카드 전 기록 채우기**: batch `reward-card-backfill`(수동, suspend 된 CronJob)이 카드 기능 전부터 담아 둔 곡 단어장 전부를
  지금 등급의 곡 카드·아티스트 카드로 연출 없이 발급하고(서명은 빈 채로), 카드가 새로 생긴 유저에게 `reward_cards_backfilled` 푸시로 알린다(탭하면 마이 탭 카드).
  안 그러면 담아 둔 곡이 많은 유저는 다른 곡과 겹치는 단어 하나를 rating 할 때마다 지금 공부하지 않는 곡의 카드가 새로 튀어나오고,
  한꺼번에 띄우면 prod 기준 1인 최대 36번의 연출이 몰린다.
  - 곡 단어장을 만든 순서대로 채워, 같은 곡은 먼저 담은 유저가 앞 순번을 받는다. 탈퇴한 유저는 뺀다.
  - 끝에 모든 카드를 조용히 발급한다 — 구버전 앱으로 rating 해 쌓인 연출이 새 앱을 켜자마자 몰리지 않게. 그래서 새 앱이 충분히 퍼진 뒤 한 번만 돌린다
    (구버전 앱은 푸시를 눌러도 카드 화면이 없고, 다시 돌리면 그 사이 쌓인 연출이 사라진다). `--no-push` 는 채우기만 한다.
  - `--dry-run` 은 아무것도 쓰지 않고 새로 생길 곡·아티스트 카드 수, 사라질 연출 수, 푸시 받을 유저 수만 로그에 남긴다. CronJob 인자를 바꿔 돌린다:
    `kubectl create job --from=cronjob/reward-card-backfill rcb-dry-$(date +%s) -n <ns> --dry-run=client -o json | jq '.spec.template.spec.containers[0].args += ["--dry-run"]' | kubectl create -f -`
- **아티스트**: 곡 카드에 달성 때의 `songs.artist_id` 를 박제한다. 아티스트 연결(batch `artist-link`)이 늦으면 연결된 뒤의 rating 에서 이어 붙이고 그때 아티스트 카드가 생긴다.
  등급은 마스터 곡 수에서 구하되 저장한다 — 구간을 다시 맞춰도 내리지 않는다.

| API | |
|---|---|
| `POST /api/flashcards/{id}/review` | 응답 `rewardCards[]` = 이 rating 으로 생긴 연출 `{kind: SONG\|ARTIST, targetId, grade, seenGrade, acquiredSeq}`, 곡 → 아티스트 순 |
| `GET /api/reward-cards/pending` | 남은 연출 전부 |
| `GET /api/reward-cards` | 곡 카드(최근 획득순, 카드 면에 싣는 가사 줄·뒷면 단어 5개·평균 R·다음 등급 진행 포함)·아티스트 카드(마스터한 곡 전부, 마스터 순) |
| `POST /api/reward-cards/songs/{songId}/issue` | `{signature: string[], lyricLineIndexes?: int[]}` 발급. 이미 발급이면 409 |
| `POST /api/reward-cards/artists/{artistId}/issue` | `{signature}` |
| `POST /api/reward-cards/{songs\|artists}/{id}/seen` | `{grade}` 등급 오름 연출을 본 등급까지 |
| `PUT /api/reward-cards/songs/{songId}/lyric` | `{lyricLineIndexes}` 1~2줄 |

- 가사 줄은 `/lyrics` 와 같은 모양이라 앱이 같은 방식으로 후리가나를 붙인다. 고르지 않았으면 서버가 기본 줄(가장 많이 반복되는 줄과 그 다음 줄)을 싣는다.
- 평균 R 은 tier 단어 중 `last_review >= song_card.created_at` 인 카드로 잰다. 다음 등급 진행은 다음 단계의 공부한 단어 수,
  완곡 뒤엔 tier 단어 90%(올림)까지의 장기기억 수다.
- 카드 색(accent·ink)은 아트에서 뽑으려면 네이티브 모듈이 필요해, 앱이 id 로 고정 팔레트에서 고른다.
